    What must my CSV files contain?

    Use UTF-8, comma-separated values and these exact ordered headers. Amounts are positive integer pence: £100 is 10000. Only GBP is accepted. No signs, decimals, leading zeros, empty fields or extra columns.

    Invoices: invoice_id,customer_id,currency,issued_date,due_date,amount_minor

    Payments: payment_id,invoice_id,paid_date,amount_minor

    IDs contain 1–64 ASCII letters, digits, dots, underscores or hyphens and start with a letter or digit. Dates are real calendar dates in YYYY-MM-DD format, years 1900–9999. Due dates and payment dates cannot precede their invoice’s issued date. Every payment must reference an invoice in this snapshot.

    Each file allows up to 2 MiB and 10,000 data records; each amount is at most 100000000000 pence. Identical repeated IDs count once. The same ID with a changed field rejects the entire snapshot. A header-only payments file means no payments; at least one invoice is required. Credits, refunds, prepayments and unallocated receipts are unsupported.

      Snapshot identity and interpretation

      Snapshot identity includes all accepted records and the as-of date, including later business dates. Reordering rows or replaying identical IDs preserves this identity. Input fingerprints still distinguish the original file bytes. An invoice overpayment never offsets another invoice’s unpaid amount.

      This is a business-date snapshot, not a historical knowledge-time ledger. It cannot establish what you knew at an earlier close, whether the source is complete, recognized revenue, tax liability or bank settlement.

      A focused local tool. This importer is separate from the historical retail reports and synthetic subscription releases. It supports your files only when they match the documented contract. No merchant formats are guessed. Synthetic examples demonstrate the workflow; no private user dataset has been supplied for this release.
